## 二、双设备方案

### 推荐分工：两张真实实验桌，互为备份

| | A 桌（LG-A01） | B 桌（LG-A02） |
|---|---|---|
| 开发板 | 现有 AIOT-3588A | 新买，**同型号** AIOT-3588A 4GB |
| 控制盒 | 现有 ESP32 + 全套传感器 + 继电器 + 12V 加热片 | 第二套 ESP32 控制盒（可以不带加热片） |
| 演示内容 | 现场加热 → 预测干烧 → 断电 → 长按复位 | 防护违规、呼叫教师、器皿靠边；拔掉开发板电源演示"控制盒 30 秒自行断电" |
| 总后台 | 平面图上两张桌都是真实终端，其余为模拟终端 | |

- **为什么同型号**：TF 卡可以直接克隆，NPU 运行库 2.3.2、RKNN 模型、开机自启都已在这个型号上验证过。买不到再选香橙派 5（`setup.sh` 也支持，但要重新装一遍、重跑 `check_npu.py`）。
- **为什么第二套控制盒**：一个 ESP32 只能接一块开发板（串口只有一个主人，两边心跳会互相掩盖）。没有控制盒的 B 桌只能放演示视频和演示数据，评委一问"这桌是真的吗"就弱了。第二套控制盒成本约 150–200 元。
- 如果预算只够板子：B 桌不接控制盒，跑演示视频 + 演示数据注入（没接控制盒时这是允许的），界面上会标"控制盒未接入"，答辩时如实说。

### 采购清单（B 桌，单价以实际为准）

开发板 + 电源 + 散热、TF 卡 ×2（一张装系统，一张做 A 桌的克隆备份，同品牌、≥ 32 GB、A2 级）、5 寸 HDMI 触摸屏、USB 摄像头 ×2（MJPG）、ESP32-S3 + SHT30 + MLX90614 + MQ-2 + 继电器 + LED / 蜂鸣器 / 按键、杜邦线。
公共：一台便携路由器（自带 Wi-Fi，不依赖会场网络）、排插、每个电源适配器贴标签。

### 装机步骤

1. **克隆系统**：A 板关机，取出 TF 卡，用 balenaEtcher / Win32DiskImager 读成镜像，写到 B 的卡上（再写一张备用卡）。
2. **B 板改成"另一台"**（克隆后必须做，否则两台在网络和总后台上撞车）：
   - 改主机名：`sudo hostnamectl set-hostname labguard-a02`
   - 删掉本机身份文件，让它重新生成：`rm -f labguard/runtime/web_token.txt labguard/runtime/web_url.txt`；清空事件：`rm -f labguard/runtime/events.db; rm -rf labguard/runtime/snapshots`
   - 检查 `runtime/config_override.yaml` 里的摄像头编号（两块板的 USB 口顺序可能不同，最好写成 `/dev/v4l/by-id/...`）
   - `python tools/check_npu.py` 确认 NPU 正常
3. **网络**：便携路由器开 DHCP 保留：电脑 192.168.8.10，A 板 .21，B 板 .22。需要联网用通义千问时，路由器用手机热点作上游；不联网时安全助手自动走规则模板，或在电脑上跑 Ollama。
4. **总后台**（电脑上）：
   ```bash
   python tools/center_demo.py --live LG-A01,LG-A02 --host 0.0.0.0 --center-url http://192.168.8.10:8210
   ```
   会生成 `runtime/center_demo_live_LG-A01.yaml` 和 `..._LG-A02.yaml`，分别拷到 A、B 板的 `labguard/runtime/` 下，在各自的 `~/.config/labguard/env` 里加一行
   `LAB_SAFETY_CONFIG=runtime/center_demo_live_LG-A01.yaml`（B 板写 A02），重启即可。
   节点密钥存在电脑的 `runtime/center_demo_live_tokens.json`，以后重启演示总后台会沿用，板子不用再拷。
5. **预演清单**（每项都实际做一遍并计时）：开机到小屏就绪多少秒；A 桌完整干烧流程；B 桌拔开发板电源，30 秒后控制盒断电、总后台显示离线；断开路由器上游，安全助手回落到规则模板；A 板坏掉时，把 A 的控制盒和摄像头插到 B 板上，B 板改用 A01 的配置继续演示（目标 5 分钟内）。

### 本次已修好的问题

`tools/center_demo.py` 原来不支持两块板同时接入：
- `--live LG-A01,LG-A02` 时两台终端写同一个配置文件，后一个覆盖前一个，A 板拿到的是 B 的密钥；
- 只监听 127.0.0.1、配置里的总后台地址也写死 127.0.0.1，局域网里的开发板连不上；
- 每次重启都换新密钥，比赛现场重启电脑后两块板都要重新拷配置。

现在每台终端一个配置文件，新增 `--host` 和 `--center-url`，密钥重启后沿用。已用两台终端实测：两次重启后密钥不变，上报返回 200；`test_center.py` 81 项全部通过。

## 三、程序优化清单

按"对比赛影响大小"排序。打 ★ 的建议比赛前做。

### A. 安全逻辑（评委最可能追问）

1. ★ **"有没有人"仍然靠装备模型推断**（`dual_inference.py` `_update_presence`，模型里没有 person 类）。人背对镜头、离得远时可能误判无人，60 秒后 R3 断电；实验服挂在椅背上又会一直算有人。这条在《评委视角审查与瘦身计划》里列为必须改，目前还没做。最省事的改法：控制盒加一个 LD2410 毫米波人体存在传感器（约 15 元，走串口状态位），和视觉取"或"；或者加一个 COCO 预训练的 person 检测。
2. ★ **加热中摄像头掉线，没有任何提醒。** 画面无效时 `_update_presence` 会把"无人值守"置为否，R3 永远不会触发；`vision_offline` 只在模型加载失败时出现，摄像头被拔掉不会报。建议：加热中且画面无效超过 10 秒，出一条警告"加热中画面中断，无法确认值守"（不断电，交给控制盒兜底）。改动在 `engine._evaluate()` 传 `person_present is None` 给状态机，状态机加一个 kind，并补测试。
3. MQ-2 阈值 1800 / 2500 是没标定的 ADC 原始值，对酒精很敏感。需要实测"酒精挥发 / 打火机放气 / 真烟"三组读数再定。
4. 红外测温点要写死"对准容器外壁 2–5 cm"，并实测一条"加热 → 沸腾 → 烧干"曲线放进技术方案。这也是温度预测最好的证据。

### B. AI 部分的证据（这个比赛的得分点）

5. ★ **没有模型评估数据。** `tools/export_model_card.py` 只导出训练时保存的指标。建议加 `tools/eval_models.py`：在留出的测试集上跑 `model.val()`，输出每类 P / R / mAP50，以及 NPU（FP16）和 .pt 的对比，直接放进 PPT。
6. ★ 量化一次"提前量"：用实测曲线算温度预测比 R1（120℃）提前多少秒发出预警，这是"事前干预"最直接的数字。
7. 事件复核已经能标"正确 / 误报"，比赛前在真实实验台跑一两个小时，统计误报率。

### C. 性能

8. 两个模型串行推理（`_process` 里先人员后器皿），每帧约 240 ms，整条流水线只有 4 fps 左右。可以：器皿模型每 3 帧跑一次（台面物品变化慢）；或两个模型放在 NPU 的不同核心上并行（需要绕过 Ultralytics，直接用 rknn-toolkit-lite2 的 `core_mask`）。
9. 单帧 120 ms 里大部分可能是 Ultralytics 在 CPU 上的前后处理，NPU 本身跑 YOLO11n 通常只要几十毫秒。直接用 rknnlite 推理还能省掉开发板上 torch 的加载时间和内存（4 GB 板子比较紧）。改之前先用 `check_npu.py` 分段计时确认。
10. 输入尺寸 640 可以试 480，INT8 量化可以再快一倍左右，但都要重新评估精度（第 5 条）。

### D. 工程与材料

11. ★ 截图都是旧版像素风格的电脑录屏，且 `slides/`、上手指南用的也是这批。比赛前在真机上重新截一套标准风格的图，并录真实实验台视频（材料要求 1080P、2–5 分钟）。
12. 许可证：Ultralytics（AGPL-3.0）在技术方案里注明；Zpix 只作可选风格，演示时不要用。
13. 清理已不用的部分：V-JEPA 2 已宣布移除，但 `jepa_link.py`、`/api/jepa/score`、`hub/jepa_worker.py` 还在；加湿片、R4 兜底、电脑大窗口（1637 行）都在瘦身计划里。答辩材料别再提它们。
14. 开发板本机控制台的口令只有 6 位十六进制，且没有输错锁定（总后台有）。会场是自带路由器的局域网，影响不大，但评委问安全时最好能说"有限次尝试"。
