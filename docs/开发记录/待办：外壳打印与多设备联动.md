## 2. 多设备联动：推算中心放在哪

现状：每台开发板（AIOT-3588A）独立完成识别 + 安全判断，总后台（`center/`）只收汇报、下发阈值和断电 / 静音指令。问题是多台设备之间怎么分工，以及"推算"（YOLO 识别、交叉验证、温度预测、安全助手）放在哪台机器上。

两条子思路：

### 思路 A：开发板为推算中心（边缘为主）

- 每台开发板在本地跑 YOLO（NPU）、规则、温度预测，结论直接驱动下位机断电。
- PC / 总后台只做汇总、显示、阈值管理、处置队列。
- 优点：断网也能工作；延迟低；安全判断不依赖网络，符合"安全判断不依赖任何界面"的约束；扩展实验桌时算力随设备线性增加。
- 缺点：每台都要 RK3588，成本高；模型更新要逐台下发；单板算力有限，做不了 V-JEPA 这类大模型。
- 可做：一台主开发板带多路摄像头 / 多个下位机（一主多从），其它桌只放下位机 + 摄像头，降低成本。

### 思路 B：PC 端为推算中心（集中为主）

- 各实验桌只放摄像头 + ESP32 下位机（或轻量终端），视频流和传感器数据汇到 PC，PC 用 GPU 统一推算后把断电指令发回。
- 优点：单台 GPU 可服务多桌，硬件成本低；模型集中更新；能跑更大的模型（V-JEPA 2、本地大模型）。
- 缺点：依赖网络，网络断了就只剩下位机本地硬规则（150℃ / 烟雾 2500 / 心跳 30 秒看门狗）兜底；多路视频占带宽；PC 成为单点故障。
- 注意：断电指令从 PC 下发时，仍只能"断电不能通电"；心跳要由 PC 上的安全判断驱动，PC 判断卡住就停心跳让下位机接管。

### 思路 C：混合（倾向）

- 安全相关的最低限度判断（规则 R1–R9、断电）始终留在本地（开发板或下位机），保证断网可用。
- 重计算（大模型问答、V-JEPA 异常检测、跨桌统计、温度预测的长期分析）放 PC / 总后台，只产生提醒不参与断电。
- 两种部署可切换：配置里选"本机推算 / PC 推算"，比赛演示时按现场设备决定。

### 待定问题

- [ ] PC 推算模式下，视频怎么传（RTSP / MJPEG / 只传截图）、延迟能否接受
- [ ] 一台开发板最多能带几路摄像头 + 几个下位机（NPU 实测单模型约 120 ms/帧）
- [ ] 联动时多台设备的心跳和看门狗如何对应（哪台断线由谁接管）
- [ ] 各赛事侧重点：计算机设计大赛偏嵌入式（倾向 A）；大创 / 挑战杯偏推广成本（可讲 B / C）
